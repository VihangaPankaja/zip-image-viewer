# Documentation

- Write for someone using or developing the app today. Use plain technical English.
- Keep setup in the root README, user tasks in `guides/`, contributor details in
  `development/`, and configuration, API and deployment details in `reference/`.
  Link each new page from `README.md` in this folder.
- Give each instruction one home and link to it elsewhere. Link official tool
  installation docs instead of copying their setup steps.
- Read the relevant source before documenting defaults, limits or behavior.
  Keep version pins in configuration, not prose.
- Put change history, migration notes and one-off measurements in PRs, not guides.
  Describe benchmark commands and how to interpret their output.
- Keep agent files limited to local rules. Keep skill steps with the skill.
- Update links when moving pages. Check relative links and documented commands.
  The roadmap is a TODO document; preserve task IDs and saved progress without
  adding CI checks for its contents or completion percentages.
